## Answer 2 — Fika (2.4.4)

CONFIRMED from Fika source (`Fika.Core`) + installed DLL IL:
- **No `SupportRigidbody`, no `Physics.Simulate`, no `simulationMode`/`SyncTransforms` in Fika.** Only physics-list call: `ReviveInteractable.RemoveRagdoll` L153-156 `UnsupportRigidbody(rb)` for a revived player's rigidbodies (unrelated to crate).
- **Fika does not patch `ServerAirDrop.ManualUpdate` or `ServerAirDrop.Init`.** Airdrop patches (`Main/Patches/Airdrops/`):
  - `ServerAirDrop_UpdateOfflineClientLogic_Patch` (postfix on `UpdateOfflineClientLogic`: copies `_offlineSyncPacket` into host world packet; `SetCritical()` when `FallingStage==Landed`). Does not touch physics.
  - `SynchronizableObjectLogicProcessor_GetSyncObjectStrategyByType_Patch` (**prefix, returns false = replaces vanilla**): `AirDrop → new ClientAirDrop(FikaBackendUtils.IsServer)`, `AirPlane → new ClientAirPlane(FikaBackendUtils.IsServer)`.
  - `ServerAirDrop_UpdateOfflineClientLogic_Patch`/`ServerPlane_…` only.
- Consequence — **who registers the crate rigidbody**: `ClientAirDrop.Init` (EFT) calls `OfflineServerLogic.Init(...)` only `if (offlineMode)`; `ServerAirDrop.Init` is where `SupportRigidbody(SyncObjectRigidbody)` happens (`ServerAirDrop.Init`, IL callers list: `…Airdrop.ServerAirDrop.Init` offset 184 is among `SupportRigidbody` callers).
  - **Host (and headless host, `IsServer` is always true there per `FikaBackendUtils` doc)**: `ClientAirDrop(offlineServerLogic:true)` → `OfflineServerLogic = new ServerAirDrop()` → Init registers the crate. `ClientAirDrop.ManualUpdate` → `OfflineServerLogic.ManualUpdate` runs. **The postfix fires only here.**
  - **Client**: `ClientAirDrop(false)`: `OfflineServerLogic == null`, `ClientAirDrop.Init` skips server logic → **no `SupportRigidbody`**, no `ServerAirDrop` instance → the postfix never fires and the fix is a host-only concern. No client-side Simulate cost from the crate.
- `SpawnAirdrop.Execute` (client-received packet; `SpawnSyncObjectSubPackets.cs` L148-189, installed IL offsets 239-298): `TakeFromPool(AirDrop)` → sets pos/rot/`_destinationPosition` → `LootItem.CreateLootContainer` → `if (!syncObject.IsStatic) InitSyncObject(...) else InitStaticObject(...)`. IL offset 239 `ldfld SynchronizableObject.IsStatic` on the **pooled object** (not `SpawnAirdrop.IsStatic` packet field, which is unused) → after `ReturnToPool` (`IsStatic=false`) clients effectively always take `InitSyncObject`. Either way `ClientAirDrop.Init`/`InitStaticObject` register **no** rigidbody on clients. Vanilla `ClientAirDrop.InitStaticObject` only forwards to `OfflineServerLogic.InitStaticObject()` (empty body in `ServerAirDrop`) and sets `IsStatic=true`, `_fallingStage=Landed`, no `SupportRigidbody`. Late-join therefore registers nothing.
- Host registration reach: `FikaHostGameWorld.InitAirdrop` (debug `InitAirdrop(null,true,pos)` works: `TakeAirdropPoint` → `TakeFromPool(AirPlane)` → `InitSyncObject`); `FikaClientGameWorld.InitAirdrop` is an empty override.

So after `ServerAirDrop.ManualUpdate` sets `IsStatic=true`, **the next frame the crate is no longer ticked** — ManualUpdate is called on the landing frame and then stops. Postfix therefore sees `IsStatic==true` once (latch not strictly required, but use `!Contains/ count>0` guard anyway). [INFERENCE: ordering "remove" runs before "update" within one PlayerTick, so the transition frame still invokes ManualUpdate.]
- `AbstractGame.GameType` in Fika: `AbstractGame.Create` (EFT) sets Offline iff `val is LocalGame`, else Online if `EftNetworkGame`, etc., else leaves `val.GameType` at its auto-property default. ## Answer 3 — Pose safety after release

**Baseline.** CONFIRMED: `AbstractApplication.Awake` sets `UpdateController.Enabled = true` (only usage of `Enabled`), whose setter does `UpdateControlledByUnity=false` (→ `Physics.simulationMode = Script`), `UpdateEnabled=false`, `SyncTransformsControlledByUnity=false` (→ `Physics.autoSyncTransforms=false`), `UpdateMode=SmoothSimulate`. `Simulation.Update` → `SmoothSimulate` runs `Physics.Simulate` only when `CanRunSimulate` (`Script && _updateEnabled`); `UpdateController.Update` → `CheckRigidbodiesDone` each frame sets `_updateEnabled = (any entry non-null && activeInHierarchy && (no checker || checker.IsVisible))` and prunes null/inactive entries. Raid default is therefore **Simulate off** unless something registered (EFT callers of `SupportRigidbody`: grenades, flare/grenade cartridges, loot `StartPhysics`, corpse ragdoll `Start/AttachWeapon`, `BrokenDoor.Breach`, tripwire, belts, lamps, suspension, **ServerAirDrop.Init**; `UnsupportRigidbody` callers in EFT: only `MgBelt`, `CorpseRagdoll.StopRigidbody`, `HideoutArea.CG_SetupItem`). The crate is the one with no matching unsupport (confirmed: `ServerAirDrop.ReturnToPool` / `ClientAirDrop.ReturnToPool` only `SetActive(false)`, which is what lets `CheckRigidbodiesDone` prune it at pool-return). Releasing the crate at landing restores EFT's designed default; Rupture's own diagnostics doc (`PERFORMANCE.md`) shows the same: frames with the gate inactive had no Simulate and `SyncTransformsClass.Update` ≈0 ms vs 1.7-2.6 ms/frame while active.

**What needs Simulate on the crate, and when it stops.** Landing detection is `SyncObjectCollisionChecker.OnTriggerEnter → SynchronizableObject.CollisionEnter → ServerAirDrop.CollisionEnter` (only caller; trigger events are produced by `Physics.Simulate`). So Simulate **must** stay on until Contact; after that nothing in the crate logic depends on PhysX events.

**Ordering before `IsStatic`.** `ServerAirDrop.ManualUpdate`: `IsStatic=true` only when `_signalFireCoroutineDone && _fallingStage==Landed`. `Landed` is set (a) directly in `CollisionEnter` for 3-point contact, or (b) at the end of `RotateAfterDrop` coroutine (up to `100*|angle|/180` frames of `RotateAround`), and `_signalFireCoroutineDone` only after `SmokeActivateHeight` reached **plus `PlaneAirdropSmoke` seconds** of unscaled time. The Landed stage has no case in the `ManualUpdate` switch, and nothing writes the server transform afterwards (`Fall/ParashuteOpening/ParashuteLanding/Swing/Torque` run only in earlier stages; `ClientAirDrop.ShakeAfterLanding` has **no callers**). CONFIRMED. So final pose is written many frames before `IsStatic`.

**Client-side lerp.** `ClientAirDrop.ManualUpdate` lerps `position/rotation` toward `_destinationPosition/_destinationRotation` with `deltaTime*DeltaTimeModificator` (asymptotic, never exactly done). On the **host** (the only place the fix fires): `OfflineServerLogic.ManualUpdate` then `UpdateOfflineClientLogic` writes `_destination*` from the *same transform* (via the packet) before the lerp, so lerp is a no-op → **zero residual delta**. (Remote clients' lerp is irrelevant: they never registered the body, and ManualUpdate stops once their packet-driven `IsStatic` moves the object to the static list — [INFERENCE] for clients since `IsStatic` packet handling wasn't traced.)

**PhysX pose with `autoSyncTransforms == false`.** All transform moves (including `RotateAround`) were already staged; `Physics.Simulate` begins with an implicit sync of pending transform changes, and Simulate ran every frame up to the landing frame, so PhysX colliders reflect the pose as of the last Simulate. Any transform write **after** the last Simulate (e.g. the final frames' `RotateAfterDrop`, which finish ≥ one signal-fire duration before `IsStatic`, so none in practice) is the only possible stale delta; with the release at `IsStatic`, the last Simulate occurs the frame the release is applied or earlier, i.e. after all transform writes → PhysX is at the final pose. Layer detail (loot trigger 22 / MeshColliders 18 / BallisticCollider 12) — layer numbers **UNVERIFIED** (prefab data not inspected); irrelevant to the argument since all are children of the same crate transform.

**EFT syncs transforms elsewhere anyway.** `PhysicsExtensions.SyncTransforms()` (= `Simulation.SyncTransforms`: `if(!autoSyncTransforms) Physics.SyncTransforms()`) callers (find_callers): `Player.ArmsLateUpdate` (`if (IsYourPlayer) Simulation.SyncTransforms()` **every frame** for the local player with a hands controller, called from `Player.ComplexLateUpdate`/`ArmsUpdate`), `PlayerSpiritBase.PlayerSync`, `LootItem.SetupBoundingCollider`, `CorpseRagdollTestApplication.LateUpdate`. `PhysicsExtensions.ForceSyncTransforms`/`Simulation.ForceSyncTransforms` have **no EFT callers except the wrappers**. `Physics.SyncTransforms` is **global** (all pending transform changes in the default scene), so residual deltas get synced the next frame the local player holds a hands controller (ballistics `BallisticUpdate` follows it). Plugins add: Rupture bootstrap/map refresh, VisitAPI narrate, 7Bpencil gizmo (all minor).

**Recommendation: sync call.** Not required for correctness (above), but since it costs nothing once, call `PhysicsExtensions.ForceSyncTransforms()` (or `PhysicsExtensions.SyncTransforms()` which respects `autoSyncTransforms==false`) **once**, immediately before the unsupport, guarded by the same one-shot latch. It guarantees PhysX has the final landed pose even if some mod wrote the crate transform after the last Simulate, and it's a single call per raid per airdrop. Use `SyncTransforms()` (EFT wrapper) rather than `Physics.SyncTransforms()` to stay inside EFT's `autoSyncTransforms` convention; both are equivalent when auto is false.
